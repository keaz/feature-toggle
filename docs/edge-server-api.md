# Edge Server API Documentation

The edge server exposes autogenerated OpenAPI documentation and an interactive Swagger UI.

- Swagger UI: http://localhost:8081/docs
  - If running on a different host/port, replace accordingly.
- Raw OpenAPI JSON: http://localhost:8081/api-doc/openapi.json

## Authentication

### OFREP endpoints: SDK key

OFREP requests authenticate with an **SDK key**:

```
<clientId>.<apiKey>
```

- `clientId` is the client's UUID and `apiKey` is the client's API key. The admin UI shows the SDK key in this form.
- The key is split on the **first** `.`. The client ID never contains a dot; the API key may.
- Send it in one of these headers (`Authorization` wins when both are present):
  - `Authorization: Bearer <clientId>.<apiKey>`
  - `X-API-Key: <clientId>.<apiKey>`

The edge forwards the client ID and API key to the backend (`GetClientInfo` and `GetFeatureByKey` over gRPC). The edge never falls back to its own configured secret, and a bare client ID is rejected.

| Situation | Status | `errorCode` |
|---|---|---|
| No `Authorization: Bearer` and no `X-API-Key` header | 401 | `UNAUTHORIZED` |
| Malformed key: no `.`, empty client ID or API key, client ID not a UUID | 401 | `UNAUTHORIZED` |
| Unknown client or wrong API key | 401 | `UNAUTHORIZED` |
| Client disabled (correct API key) | 403 | `FORBIDDEN` |
| Context `environment_id` differs from the client's environment | 401 | `UNAUTHORIZED` |
| `Web` client and `Origin` missing or not in the client's web origins (see [CORS](#cors)) | 403 | `FORBIDDEN` |
| Backend unavailable or failing (after retries) | 502 | (plain-text body) |

401 and 403 responses have this body:

```json
{
  "errorCode": "UNAUTHORIZED",
  "errorDetails": "SDK key is invalid"
}
```

Authentication failures are never retried against the backend; only transient gRPC failures (for example `Unavailable`) are retried, and they end in 502 if the backend stays unavailable.

The edge caches authentication results, keyed by client ID and a SHA-256 hash of the API key:

- Successes are cached for `cache.client_ttl_secs` (default 300 seconds). A client that is disabled or whose API key is rotated stays accepted by the edge for up to that TTL.
- Rejections (bad key, unknown client, disabled client) are cached for 30 seconds, so a repeated bad key reaches the backend once. A client created or re-enabled after a rejection is rejected for up to that long. Transient backend failures are never cached.
- Because the API key hash is part of the key, a cached success never accepts a different API key, and a cached rejection never blocks the correct one.

The backend checks the API key before the client status, so a wrong key for a disabled client gets 401, not 403.

### `/evaluate`: edge-configured client

`POST /evaluate` takes no caller credentials. It always evaluates as the client configured in the edge's `config.toml` (`client_id` / `client_secret`).

## CORS

CORS applies to `/evaluate` and both OFREP endpoints.

**Preflight** (`OPTIONS`): always `204 No Content` with

```
Access-Control-Allow-Origin: <request Origin>
Access-Control-Allow-Methods: POST, OPTIONS
Access-Control-Allow-Headers: Authorization, X-API-Key, Content-Type, If-None-Match
Access-Control-Max-Age: 600
Vary: Origin
```

A preflight carries no credentials, so the client is not checked.

**Actual request**: decided by the authenticated client (for `/evaluate`, the edge-configured client):

- `Web` client and `Origin` in the client's web origins: the request is served and the response carries
  ```
  Access-Control-Allow-Origin: <Origin>
  Access-Control-Expose-Headers: ETag
  Vary: Origin
  ```
- `Web` client and `Origin` missing or not allowed: `403` with `Vary: Origin`. OFREP returns `{"errorCode": "FORBIDDEN", ...}`; `/evaluate` returns `{"error": "FORBIDDEN", "message": "..."}`.
- `Backend` client: the request is served without CORS headers, whatever the `Origin`.

## Endpoints

- GET /health
  - 200 OK when the edge server is connected to the backend stream
  - 503 Service Unavailable otherwise

- POST /evaluate
  - Evaluates one flag as the edge-configured client (see [Authentication](#evaluate-edge-configured-client)).
  - Request body (application/json):
    ```json
    {
      "flagKey": "discount-banner",
      "context": {
        "bucketingKey": "user-123",
        "plan": "premium"
      }
    }
    ```
    `bucketingKey` is required. Other context fields are attributes for targeting rules. An optional `environment_id` attribute must match the configured client's environment.
  - Response body (application/json):
    ```json
    {
      "flagKey": "discount-banner",
      "value": true,
      "variant": "enabled",
      "reason": "TARGETING_MATCH"
    }
    ```
    `errorCode` (for example `FLAG_NOT_FOUND`, `ENVIRONMENT_NOT_FOUND`) and `metadata` are present only when set.
  - Errors: `400` invalid body, `401` `environment_id` does not match the client's environment, `403` origin not allowed (Web client), `502` backend unavailable.

- POST /ofrep/v1/evaluate/flags/{key}
  - OFREP single-flag evaluation. Requires an SDK key (see [Authentication](#ofrep-endpoints-sdk-key)).
  - Request body (application/json):
    ```json
    {
      "context": {
        "targetingKey": "user-123",
        "plan": "premium"
      }
    }
    ```
  - Response body (application/json):
    ```json
    {
      "key": "discount-banner",
      "value": true,
      "reason": "TARGETING_MATCH",
      "variant": "enabled"
    }
    ```
  - Errors: `400` empty `targetingKey`, `401` / `403` as described above (including `environment_id` mismatch), `404` `FLAG_NOT_FOUND`, `502` backend unavailable.

- POST /ofrep/v1/evaluate/flags
  - OFREP bulk evaluation for all cached flags of the caller's team. Requires an SDK key.
  - Accepts `If-None-Match` for ETag cache validation and `flagConfigEtag` / `flagConfigLastModified` query metadata for OFREP event-triggered re-fetches.
  - Request body (application/json):
    ```json
    {
      "context": {
        "targetingKey": "user-123",
        "plan": "premium"
      }
    }
    ```
  - Response body (application/json):
    ```json
    {
      "flags": [
        {
          "key": "discount-banner",
          "value": true,
          "reason": "TARGETING_MATCH",
          "variant": "enabled"
        }
      ],
      "metadata": {
        "version": "etag-value"
      }
    }
    ```
  - Returns `304 Not Modified` with no body (and the `ETag` header) when `If-None-Match` matches the current ETag. The ETag covers the flag set, the client environment and the evaluation context (`targetingKey` and attributes), so a changed context gets a fresh `200`. `If-None-Match: *` is ignored.
  - Browser clients can read the `ETag` header because it is listed in `Access-Control-Expose-Headers`.

### Example

```bash
curl -X POST http://localhost:8081/ofrep/v1/evaluate/flags/discount-banner \
  -H "Authorization: Bearer <clientId>.<apiKey>" \
  -H "Content-Type: application/json" \
  -d '{"context":{"targetingKey":"user-123"}}'
```

You can explore and try requests directly via the Swagger UI.
